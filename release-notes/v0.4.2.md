# oh-my-deepseek v0.4.2

## 修复插件安装、更新与旧环境兼容问题

本版本修复插件市场中点击“更新”后 `pnpm exited with code 1`，以及部分更新操作实际没有升级插件的问题。

- 旧版 pnpm 或外部 Store 创建的 profile 会在首次变更插件时自动迁移到客户端自带 pnpm 11.20.0 与专用 Store
- 迁移前会备份 `node_modules`、`package.json`、锁文件和 workspace 配置；迁移失败或上次迁移中断时会恢复原文件
- 更新 npm 插件时明确安装目录中的目标版本，完成后校验实际安装版本，避免按钮执行成功但版本未变化
- 插件文件缺失时显示“修复”，可直接重新安装；已从社区目录下架的依赖仍会显示，可修复或卸载
- pnpm 失败提示会保留关键 `ERR_PNPM_*` 信息，并隐藏 URL 和认证参数中的凭据
- Windows 使用正确的内置 Corepack 路径，无需依赖系统 pnpm

## 验证

- macOS arm64 与 Windows x64 打包资源检查
- 全新插件安装、更新和卸载
- pnpm 9、pnpm 10、自定义 virtual store 的旧 profile 迁移
- 插件缺失修复、未收录插件卸载
- 模拟迁移失败后的完整回滚与后台重启
- Harness 崩溃清理与基础启动烟测

> Windows x64 产物在 macOS 上交叉打包；安装资源和 Corepack 路径会自动检查，最终交互仍建议在 Windows 真机确认。
